# पीपा परंपरा — Pipa Parampara

A Hindi-first, source-based community archive for the Pipa Kshatriya Darji / Pipa
Kshatriya Rajput community: the life of पीपाजी in 33 episodes, the verse corpus,
Samdari Dham, the 204 villages of the five pattis, the pilgrimage sites, the
organisations, and the competing accounts of the tradition's history.

Published at **https://pkds.pages.dev**.

Everything is hand-written static HTML generated by a build script. No framework,
no runtime dependencies, no external CDN, no analytics.

## Why it is built this way

The community's history is contested — on dates, on lineage, and on the caste
boundary itself. This site does not settle those arguments. It puts the competing
accounts side by side, attaches a source to each, and labels how firm the ground
is:

| Badge | Means |
| --- | --- |
| 🟢 प्रमाणित | Documented in a dated, citable source |
| 🟡 परंपरा | Carried by living tradition, no firm document |
| 🔵 स्थानीय | Local testimony — a village, a family, a temple |
| ⚪ मतभेद | Sources disagree; both positions are shown |

That convention is the point of the project, not a decoration.

## Run it locally

```bash
npm run build
npm run serve        # http://localhost:4321, extensionless like Pages
```

Output goes to `dist/` (about 4 MB). `build.mjs` wipes and recreates it on every
run, so never edit files there. `tools/serve.mjs` is a small static server that
resolves `/pipaji` to `pipaji.html`, the way Cloudflare Pages does — a plain file
server would 404 every internal link, since the site's links carry no extension.

Optional checks, which need `npm install` (`playwright-core` is the only dev
dependency) and a server running on `:4321`:

```bash
npm run verify   # console errors, broken links, overflow, search, filters, no-JS
npm run audit    # contrast, tap targets, heading outline, page weight
npm run og       # 17 social cards → assets/og/
```

`tools/verify.mjs` drives real Chrome across every page at 1280 px and at
320/390/768/1180 px, plus the search dialog, the verse filter, the village table,
preference persistence, print styles, and the whole site with JavaScript off.
Nothing in `tools/` ships to production.

## Deploy

`dist/` is plain static files — no Node on the host, no environment variables, no
secrets, no deploy command. It deploys to **Cloudflare Pages**:

1. Workers & Pages → Create → *Continue to Pages* → connect this repository.
2. Framework preset **None**, build command `npm run build`, output directory `dist`.
3. The site lands at `https://pkds.pages.dev`. A push to `main` redeploys it.

Pages builds `dist/` and serves it from the edge; there is no runtime to patch. No
wrangler config, no deploy token.

Any static host will serve `dist/` unchanged: Netlify, Vercel, S3, plain nginx.
Blogger cannot host this — it is a publishing platform, not a static file host, so it
has no way to serve these pages, the `assets/` tree or `manifest.webmanifest`.

### The origin lives in one file

`site.config.mjs` holds `SITE.url`. Canonical tags, `sitemap.xml`, `robots.txt`,
`llms.txt`, `feed.xml`, JSON-LD `@id`s, `og:image` paths and the address printed on
verse posters all derive from it. Page modules write `ORIGIN_PLACEHOLDER` and
`build.mjs` substitutes the real origin at build time, so changing the address is:

```bash
# edit SITE.url in site.config.mjs, then:
npm run build && npm run og
```

Everything above the fold is relative-linked, so the site also works from a
subdirectory (e.g. `user.github.io/repo/`) if `SITE.url` includes that path.

  pages/*.mjs          one module per page; default export { slug, html }

  styles.css           design system — paper/ink/madder/gold, Devanagari type scale,
                       theme presets, search + prefs dialogs, book reader, print rules
  app.js               progressive enhancement only: nav, prefs, search, filters, quiz,
                       village table, citations, book progress, translation loader
  fonts.css            @font-face block for the self-hosted woff2 files

  docs/                scans cited by the source footers (see "Rights" below)
  og/<slug>.png        one 1200×630 share card per page

  icon-180.png, icon-512.png, favicon.svg

repository; see [Scope](#scope).

## Conventions

- **Hindi first.** English appears only for proper nouns and citations. `en.html`
  is written by hand; no page is machine-translated at build time.
- **Every claim carries a source and a badge.** Competing narratives sit side by
  side; the site does not adjudicate the caste-boundary debate.
- **Names.** Prose says पीपाजी and खेतारामजी, not the bare forms; verse, institution
  names and compounds keep the original.
- **Privacy.** Only published office-bearers and office contacts appear. No household
  or member directory, ever.
- **Works without JavaScript.** Text, tables and verses are static HTML; JS only adds
  search, filtering, tabs, the quiz and theme controls.
- **Numerals follow the reader.** Western digits (`204`) are the default; the `Aa`
  dialog switches every count to Devanagari (`२०४`) and remembers the choice. The
  build emits both forms inside `<span class="num">`, so the switch is pure CSS and
  nothing re-renders or flashes. Source files stay in Devanagari; `<head>`, JSON-LD
  and sitemaps always get plain digits.

## Reading features

- **Search** — `/` or `⌘K` from any page, scoped to all / verses / villages / pages.
  `/khoj` also accepts `?q=`. Devanagari is normalised (combining marks, spelling
  variants) so "सुई" and "सुंई" find the same verse.
- **Search in Latin script** — every entry carries romanised spellings built at build
  time ("समदड़ी" → `samadari`, `samdari`, `smdari`), so a phone keyboard typing
  "samdari", "pachpadra" or "pipaji" finds the same pages, with a vowel-skeleton
  fallback for spellings the index did not anticipate.
- **Verse permalinks** — each verse is `/vani#pad-N`, with a link button that
  copies the exact URL and highlights it. The index has one entry per verse, so a
  query lands on the verse, not the whole collection.
- **Preferences** — the `Aa` dialog sets theme (paper / night / soft / contrast),
  font, text size, measure, motion, numerals and language. Stored in `localStorage`
  and applied before first paint, so there is no flash.
- **Book mode** — `/granth` is the corpus laid out as a book: sticky TOC,
  reading-progress bar, print styles.
- **Social cards** — every page ships its own `og:image` (`assets/og/<slug>.png`),
  rendered from the built `<h1>` and description by `npm run og`.
- **Verse posters** — `पोस्टर` draws a 1080×1350 keepsake card on a canvas (seal,
  verse, source, address). Phones get the native share sheet; desktop downloads the
  PNG. WhatsApp in the citation row opens `wa.me`, because that is where this
  audience shares.
- **Translation** — the language select sits in the `Aa` dialog and does nothing
  until the reader picks a language. It then writes the `googtrans` cookie and
  reloads once, which is the only path that reliably lands first time; scroll
  position is restored, a banner reports loading → done → failed with a retry, and
  Google's own toolbar is hidden. "मूल हिन्दी" clears the cookie.
- **Print / cite / share** — every page's citation row carries copy-citation,
  print, and web-share (with a clipboard fallback).

## Machine-readable surface

- `sitemap.xml` — 17 URLs, `lastmod` from the build date.
- `robots.txt` — allows everyone, disallows `/404`, explicit rules for GPTBot,
  ClaudeBot, Google-Extended, PerplexityBot and friends.
- `llms.txt` / `llms-full.txt` — a curated map of the archive for language models.
- `feed.xml` — Atom feed of the dated events on `/samachar`.
- `manifest.webmanifest` + icons — installable, offline-tolerant shell.
- Per-page JSON-LD: `WebSite` + `Organization` + `WebPage` + `BreadcrumbList`
  everywhere, plus `Person` (pipaji), `Book` (granth), `FAQPage` (prashnottari),
  `ItemList` of `TouristAttraction` (tirth), `HinduTemple` + `Event` (samdari),
  `ItemList` of `Event` (samachar), `Article` (en), `SearchResultsPage` (khoj).

## Corrections

Wrong facts and rights complaints are both taken seriously, and both go to
**pkds.webteam@gmail.com**. Say which page, which line, and if possible which source.
Factual fixes are checked against a source and applied, or moved into a ⚪ मतभेद card
if the sources genuinely disagree. Removal requests for third-party material are
acted on immediately.

## Scope

What this project intentionally leaves out, and why:

- **The Sagwara household and mobile directory, and the patron phone list.** Only
  publicly published office-bearer contacts appear. This is a privacy commitment, not
  an oversight.
- **The `research/` folder.** It holds those contact directories and OCR of
  in-copyright print books, so it is kept local. Every source the site relies on is
  cited on the page that uses it.
- **Unverified claims presented as fact.** They either carry a ⚪ मतभेद card, a
  🔵 स्थानीय label, or a note in the working files.
- **Analytics, trackers, cookies, ads, comment systems, server-side code.** The only
  network call the site can make is the optional Google Translate widget.

Built by readers of the tradition, for readers of the tradition. Corrections are
welcome — that is how an archive like this stays honest.
